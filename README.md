# Bilibili Accelerator for Android

**一个致力于改善哔哩哔哩客户端视频加载体验的 LSPosed 增强模块。**

本项目是 [realzza/bilibili-accelerator](https://github.com/realzza/bilibili-accelerator) 的非官方 Android 移植版。

你是否遇到过明明网速很快，但看 B 站视频时依然频频卡顿、一直在转圈缓冲的情况？这通常是因为 B 站为了节省成本，为你分配了一些质量不稳定的边缘节点（甚至是他人的个人宽带节点）来加载视频。
本模块通过在后台智能接管 B 站客户端的视频加载过程，将这些容易卡顿的低速节点无缝切换至**官方的高速 CDN 服务器**，从而让你告别视频缓冲的烦恼。同时，模块内置了直观的**实时数据看板**，加速效果一目了然。

---

## 核心特性

本模块在底层对视频流与直播流请求进行智能拦截、重定向与并发调度，全面保障播放体验：

* **PCDN 深度识别与调度源站还原**：智能阻断低质 P2P/PCDN 节点与非标端口，强制回退至官方优质骨干网；针对 `mountaintoys.cn` / `szbdyd.com` 等调度流，识别并提取 `xy_usource` 参数动态恢复原生官方 CDN，并在 Playinfo 备用地址列表中完备保全。
* **MCDN 调度策略颗粒度**：支持 `proxy-all`（默认推荐，通过云厂商官方 CDN 全量中继代理所有 MCDN 节点）与 `proxy-v1`（仅针对 `/v1/resource/` 资源接口走官方中继代理，常规中继流直连原节点以避免 UPOS 403 鉴权失败）双档位自适应调度。
* **Akamai 节点签名保护与全 Akamai 供体镜像合成（All-Akamai Donor Synthesis）**：自动识别海外与官方 Akamai 鉴权节点，默认保留专属 HMAC Token 签名安全放行（`akamai-pass`）。在开启重定向 Akamai 且全部候选节点皆为 Akamai（海外无普通官方镜像供体）的特殊场景下，智能允许以 Akamai 链接作为供体合成 UPOS 镜像并发池，配合熔断黑名单自动剔除 403 节点，海外用户亦可安全享受 BTR 多源分片加速。
* **BTR 多源并发分片加速（Bilibili Thread Ripper）**：
  * **自动动态线程调节（Auto Concurrency）与开播冲刺（Startup/Seek Sprint）**：开启 Auto Concurrency 时，基准并发设为 `min(用户上限, 6)`；开播与 Seek 冲刺阶段并发目标为 12（按梯级 `[2, 4, 6, 8, 12, 16]` 钳位至用户并发上限，在用户上限 >= 8 时开播冲刺阶段达到 8~12 线程并发拉取并严格受控防 412/429）。起播完成（累计拉取 >=4MB 或队列持续非饱和 >=3s，上限 30s）后每 2.5s 平滑回落一档至基准并发。运行期升档严格依赖真实播放压力（播放器卡顿 / 低缓冲饥饿 / 持续队列拥塞 / 慢响应），并采用 5s 滑动窗口（250ms 采样桶）吞吐量评估，要求 >=8% 净收益（>=1.08x）方可提交档位，否则自动回退并休眠 90s，防止盲目升档锁定在最高 16 线程引发风控。设置中提供开启/关闭开关与自定义 2~16 线程滑块。
  * **动态对冲与慢节点实时救援（Early Hedge & Straggler Rescue）**：对冲延迟根据切片 EWMA 往返时延动态计算（范围 250ms~1200ms），并在首发请求经过 250ms 宽限期后持续监控其实时传输速率；若首发请求速率跌破平均网速的 55% 或发生 >=350ms 的分片中断滴流，提前唤醒对冲线程介入抢拉，杜绝长尾慢分片导致播放器转圈。
  * **自适应切片尺寸（Dynamic Chunk Size）**：根据视频总体积与清晰度在 256KB~2MB 间自适应匹配分片大小，音频采用 128KB 极低延时切片，高码率与 4K 大视频自动放大至 1MB~2MB，大幅降低高吞吐下的并发 HTTP 请求与头部握手开销。
  * **自定义白名单 CDN 节点池**：支持用户在设置中自定义配置、增删多达 32 个白名单 CDN 镜像节点，允许海外与专线用户灵活指定参与并发拉取的节点池。
  * **OkHttp 独立连接池与 HTTP/1.1 多物理连接并发**：底层请求全面升级为高性能 OkHttp 栈，显式采用 HTTP/1.1 独立物理连接池（保留 Keep-Alive 复用）。针对哔哩哔哩 UPOS CDN 边缘节点对单 TCP 连接限速的特性，强制每并发使用独立物理 TCP 通道与拥塞窗口，杜绝 HTTP/2 单连接复用导致的流限速折叠、TCP 队头阻塞与 RST_STREAM/GOAWAY 异常，实现真正的多 TCP 窗口并发带宽倍增。
  * **多源 CDN 并发拉取**：智能合成安全的大陆同源 UPOS 镜像与自定义候选池，解决客户端备用地址缺失或调用时序倒置问题，实现真正的跨 CDN 并发负载。
  * **0KB 空响应包与截断熔断**：严格校验探测包与分片字节完整性，遭遇 0KB 空包或截断时立即熔断惩罚并自动无缝 Failover 故障转移；针对未知长度流严格使用 HTTP/1.1 Chunked 封包传输，并在中途断流时终止传输而非静默返回 EOF，杜绝播放器假死转圈。
  * **音频轨道隔离与防混流**：精准识别 DASH 独立音频流（302xx），采用 128KB 极低时延切片与 2 线程隔离并发，杜绝与视频大分片争抢带宽，彻底解决音画不同步。
  * **剧集加速专属模式（Episode Acceleration）**：针对番剧、电影、纪录片等 PGC 内容提供专属加速开关与兼容模式调度。精准识别 OGV/PGC 内容，自动隔离港澳台及海外专属版权镜像，防止跨区 403 鉴权失败；试看片段（is_preview）与硬件级 DRM 加密流智能安全放行，杜绝播放器假死。
  * **直播流多源并发加速与多源鉴权保护（Live Concurrency Acceleration）**：完整移植 BTR 实验性直播加速内核（live-core.js）。深入拦截与解析直播 `getRoomPlayInfo` 接口响应（提取多官方线路并剔除 PCDN），支持 fMP4 HLS 播放列表与切片解析；维护官方直播节点池（包含国内节点与海外专属 `ov-gotcha` 节点），根据 TTFB 首字节延迟与 EWMA 分值动态优选；分片对冲下载严格保留目标候选节点的独立鉴权 Token（杜绝跨 CDN 节点签名错配导致 403 封禁）；配合 0KB 空包即时熔断、前瞻切片后台预取队列与持续 FLV 直播流竞速首播，全方位保障秒开与流畅。
* **点播智能自适应路由（Auto VOD Routing，非 BTR 模式）**：当关闭 BTR 并发分片加速时，自动启用轻量级自适应路由引擎（移植自 upstream v0.5.0 routing 架构）。告别单节点静态替换，采用 Shaka 双半衰期 EWMA 精准跟踪真实下行吞吐与播放器卡顿（Stall / Buffer Hunger），在卡顿或带宽不足时自动挑选候选节点执行 768KB 测速竞速，要求胜出节点达到 >=1.5x 带宽增益方触发平滑切换，并持久化各地域与网络环境下的测速优选历史。
* **数据可视化看板**：配有直观的实时统计面板、最近拦截日志与分流详情染色。

## 安装与激活

### 前置要求

* 已 Root 的 Android 设备
* 已安装并激活支持新版标准的框架（如最新版的 [LSPosed](https://github.com/LSPosed/LSPosed) 或 Vector 等）
* 哔哩哔哩官方客户端（支持标准版 / 概念版 / 国际版 / HD 版等）

### 激活步骤

1. 下载最新版的 `app-release.apk` 并安装。
2. 打开你的框架管理器（如 **LSPosed Manager**），在“模块”列表中找到 **Bili Accelerator** 并勾选启用。
3. 在模块的作用域设置中，勾选你需要加速的 B 站客户端（如：`tv.danmaku.bili` / `com.bilibili.app.in` / `com.bstar.intl` 等）。
4. **强行停止**（杀掉后台）哔哩哔哩客户端。
5. 重新打开哔哩哔哩。
6. 打开本模块的 APP，若顶部状态显示 **“✅ 已激活”**，即代表配置成功。此时去 B 站随意播放一个视频，即可在面板中观察到拦截与重定向的计数正在增加。

## 遇到问题？

**Q1: 打开模块 APP 显示“未激活”怎么办？**

* 请检查框架管理器中是否已勾选启用本模块，并且**正确勾选了哔哩哔哩客户端作为作用域**。
* 每次更新模块或修改作用域后，必须**强行停止**（杀掉后台）哔哩哔哩客户端，然后重新打开才会生效。
* 如果确认操作无误但依然显示未激活，请尝试重启手机或重启框架服务。

**Q2: 播放视频时一直转圈缓冲，或者提示加载失败？**

* 可能是 B 站服务器临时调整了策略，或者你的网络运营商对我们重定向后的高速节点连接不佳。
* 部分极旧或最新的 B 站客户端版本可能会更改底层的播放机制。建议你在框架中暂时关闭本模块，排查是否为网络本身的问题。如果确认是模块导致，请在 Issue 中反馈你使用的 B 站版本号。

**Q3: 播放了视频，但面板里的拦截/重定向统计数据一直为 0？**

* 请先确认模块状态是否为“已激活”。
* 在非高峰时段或播放冷门视频时，B 站可能本身就为你分配了官方的优质 CDN，没有触发模块的拦截规则，此时计数不增加属于正常现象。
* 如果持续多天、播放任何视频都不增加，可能是 B 站客户端的更新导致模块的拦截机制失效，欢迎你携带日志向我提交 Issues，并请关注模块的后续更新。

## 编译指南

如果你想自行编译此项目：

1. 使用 **Android Studio** 打开 `bilibili-accelerator-android` 项目。
2. 等待 Gradle 同步完成后，点击菜单栏：**Build > Build Bundle(s) / APK(s) > Build APK(s)**。
3. 或者在终端运行以下命令：
```bash
# 构建正式 Release 版本
./gradlew assembleRelease

# 或构建开发 Debug 版本
./gradlew assembleDebug

```

4. 编译成功后，在 `app/build/outputs/apk/release/` 目录下获取 `app-release.apk` 并安装。
